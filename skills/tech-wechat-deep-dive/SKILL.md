# 科技公众号深度解读写作

当用户提供科技新闻、发布说明、产品更新或行业素材并要求写公众号文章时，使用本 Skill。

目标不是复述新闻，而是解释这件事为什么值得写。

## 工作流

1. 先提炼核心判断，不要急着写正文。
2. 分开列出事实和判断。
3. 找一个反常识切口。
4. 用事实证明判断，而不是堆观点。
5. 技术细节保留关键术语，但立刻翻译成人话。
6. 正文每一段必须推进新信息。
7. 结尾收紧成一句更硬的判断，不喊口号。

## 核心判断

写前先把素材压成一句话。

可用来思考的句式：

```text
这件事真正值得写的，不是 X，而是 Y。
表面看是 X，实际说明 Y。
它的价值不在功能，而在结构变化。
这件事意味着某种行业趋势已经开始出现。
```

正文里不要频繁照搬这些句式，落笔时用具体事实自然推出判断。

## 事实与判断

事实回答：

- 谁发布了什么？
- 什么时间发生？
- 新增了什么能力？
- 涉及哪些对象？
- 有什么限制、门槛、规则？
- 官方关键表述是什么？

判断回答：

- 它改变了谁的处境？
- 它重写了什么规则？
- 谁受益，谁被削弱？
- 它为什么不是孤立小事？
- 它和过去相比有什么不同？

正文以判断为主线，事实只作为论据。

## 结构

1. 标题：有传播性，但不标题党。
2. 开头：用最反常识、最具体的事实抓住读者。
3. 中段一：补关键细节，证明这事不是空壳。
4. 中段二：提出真正的问题。
5. 中段三：解释更深层价值或行业变化。
6. 结尾：收束成一句更硬的判断。

## 语言

句子尽量短。少空话。判断清楚。有人感，但不自我表演。

优先写：

```text
未接入的小程序，无法被微信 AI 调用。
这句话比“微信 AI 内测”更重要。
开发者过去争的是用户点击。现在还要争 AI 选择。
```

避免：

```text
如果只看表面……
真正值得注意的是……
更深层地看……
这背后说明……
不难发现……
值得一提的是……
随着技术不断发展……
在 AI 快速发展的今天……
```

## 技术细节处理

不要堆术语。

保留关键术语，然后解释它对判断有什么作用。

示例：

```text
MCP 的作用不是让模型更会聊天，而是让模型能连接外部工具。AI 从“回答问题”变成“调用服务”，靠的就是这类接口。
```

## 反常识切口

优先找这几类：

- 表面利好，实际让出权力。
- 表面功能更新，实际分发规则变化。
- 表面技术升级，实际商业模式重排。
- 表面工具开放，实际平台建立索引。

## 检查

定稿前检查：

- 前 3 段是否进入核心问题？
- 是否有明确反常识判断？
- 每段是否有新信息？
- 事实是否服务判断？
- 技术术语是否翻译成人话？
- 是否删掉通稿腔和 AI 报幕句？
- 结尾是否有一句能被读者记住的硬判断？
