# 一流编导改脚本

把已经能表达意思的草稿压缩成可以直接念、可以拍、可以由画面证明的口播稿。优先保留事实、冲突和用户回报，不为完整而保留句子。

## 收集约束

开始前确认或合理推断：

- 原始口播稿。
- 目标平台、受众和时长。
- 必须保留的事实、数字、品牌名、术语与合规提示。
- 已有证据：实测结果、截图、来源、案例、用户原话或可演示动作。

缺少证据时继续完成可安全执行的删改，同时把无法证明的关键句列入“待补证据”。不得为增强说服力编造数字、体验、对比或用户反馈。

## 执行流程

### 1. 先保护事实

先锁定不能误删或改义的内容：

- 核心结论和必要因果关系。
- 已核实的数字、时间、来源与适用边界。
- 产品或方法真正执行的动作。
- 风险提示、限制条件和引用中的用户原话。

把“事实”“创作者判断”“用户评价”“待核实说法”分开处理。只把事实写成确定语气。

### 2. 做第一轮删除

为每句话只分配一个主要功能：钩子、问题、动作、证据、对比、转折、边界或行动引导。执行以下删除：

- 没有明确功能的句子，删除。
- 与前文重复同一信息的句子，保留更短、更具体的一句。
- 问候、预告、总结式复述和不推动理解的过渡，删除。
- “非常好、很强大、特别方便、十分专业”等自我评价，先删除，不急着改写。
- 连续罗列功能但没有用户场景的内容，压缩成一个具体任务。
- 同时索要点赞、关注、评论、转发的机械收尾，只保留一个与内容有关的动作。

不得删掉理解结论所需的因果桥梁，也不得为了短而删除必要限制。

### 3. 把形容词换成证据

逐一检查旁白中的形容式判断。优先改写成以下任一形式：

1. **动作**：产品或人具体做了什么。
2. **数字**：时间、步骤、数量、前后变化或结果口径。
3. **场景**：用户在什么时刻遇到什么问题，随后发生什么。
4. **对比**：使用前后少了哪些动作，新增了什么结果。
5. **演示**：镜头能够录到的输入、过程和输出。

没有证据支撑时，删除该判断或改成明确的个人观点，不得把形容词换成虚构数字。形容词只在表达用户原话或主观感受时谨慎保留，并标清是谁的评价。

需要转换示例时，读取 [references/transformation-patterns.md](references/transformation-patterns.md)。示例只用于理解转换方法，不得把示例数字套用到新稿。

### 4. 改成用户会说的话

把行业定义改成用户能观察到的问题、动作或结果：

- 优先使用用户搜索、抱怨和提问时会说的词。
- 把抽象名词改成主语明确的主动句。
- 保留必要术语时，紧接一句人话解释它会改变什么。
- 一句话只讲一个信息点；避免一口气堆三个以上并列概念。
- 用“你原来要做什么—现在谁替你做—最后拿到什么”解释工具价值。

不要假装粗俗就是口语化。保持受众熟悉的词汇和创作者原有语气。

### 5. 做第二轮删除

完成改写后再删一次：

- 删除已经被数字或动作证明的评价句。
- 删除观众理解结论不需要的原理和背景。
- 删除不能改变观众判断的例子、同义句和补充说明。
- 删除换一个品牌名仍然成立的通用宣传语。
- 合并连续短句中仅为停顿存在的文字，保留自然呼吸点。

对每句话追问：“删掉它，观众会少知道什么？”如果答案是“没有”，删除。

### 6. 校准口播与时长

- 使用主动语态和具体动词。
- 保持一口气能念完一句；长句优先拆成“动作—结果”。
- 让关键数字单独落句，给画面和停顿留空间。
- 按创作者真实语速估算时长；未知时按每秒约 3.5—4.5 个汉字粗估，并预留 5%—10% 停顿空间。
- 超时先删重复、背景和功能清单，不先删证据。

### 7. 做终稿审计

交付前逐项检查：

- 每句话是否承担一个明确功能？
- 每个确定性判断是否有证据、来源或可演示动作？
- 是否仍有“强大、专业、便捷、领先、智能”等旁白自夸？
- 是否把术语翻译成用户能观察到的变化？
- 删除产品名后，文案是否仍像任何品牌都能使用？如果是，补回独特动作或结果。
- 开头承诺是否在正文中得到兑现？
- 实际念一遍是否顺口，时长是否满足要求？
- 删到最后是否仍保留事实、观点和用户回报？如果什么都不剩，原稿主要由正确废话组成，应返回素材层补证据，而不是继续润色。

## 交付格式

用户只要成稿时，直接交付纯口播终稿，不添加方法论讲解。

用户要求优化或诊断时，按以下顺序交付：

1. **可直接念的终稿**。
2. **删改摘要**：最多 5 条，说明删掉了什么类型的信息。
3. **待补证据**：只列会影响可信度的关键缺口；没有则省略。
4. **时长估算**：列出汉字数、估算语速和时长。

用户要求逐句对照时，再增加“原句—处理—原因”表。不要默认展示冗长的内部分析过程。
