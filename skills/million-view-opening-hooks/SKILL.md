# 百万播放爆款开头

把一个选题压缩成观众为什么现在不能划走的单一理由，并在前 12 秒兑现第一份信息回报。开头负责建立观看承诺，不用情绪替代内容价值。

## 工作流程

### 1. 先锁定用户回报

先写清一句话：

> 给【哪类观众】看【什么问题】，看完能得到【什么具体判断、方法或结果】。

如果输入只是一个公开事实或新闻，继续追问“这件事与观众正在做的决定有什么关系”。不要把人人都知道的事实当成钩子。

### 2. 选择一种主结构

根据素材选择最匹配的一种，不要机械叠加五种结构：

| 结构 | 优先使用的场景 |
| --- | --- |
| 连环否定 | 需要推翻一组具体、常见且可核实的旧认知 |
| 一招搞定 | 痛点很强，且确实存在低门槛、短路径的解决方法 |
| 只问不答 | 选题本身存在强因果谜题或反常识结果 |
| 树立敌人 | 观众共同反感一种错误做法、误导话术或低效流程 |
| 放大损失 | 划走会错过的价值、时间或成本真实且可以具体化 |

需要公式、原案例和边界时，读取 [references/hook-patterns.md](references/hook-patterns.md)。

### 3. 写出前 12 秒

按以下节拍输出：

- **0–3 秒**：第一句话通常控制在约 10–14 个汉字，直接给冲突、利益、问题或损失。
- **3–8 秒**：增加一个新问题、对比或证据，扩大信息缺口。
- **8–12 秒**：交代观众能拿到的答案，并给第一条有效信息。
- **12–18 秒**：自然进入正文，避免钩子很猛、后文突然泄气。

每一句都必须承担“吸引、证明、交付、承接”中的至少一种功能。删掉客套、履历、重复解释和空泛形容词。

### 4. 让钩子由正文兑现

检查正文能否在合理时间内回答开头承诺：

- 使用数据时注明日期、来源和口径。
- 使用“一招搞定”时，方法必须真实简单；复杂任务不能伪装成一秒完成。
- 使用“只问不答”时，最迟在前 12 秒给出答案方向，不能只吊胃口。
- 使用“树立敌人”时，针对错误观点、行为或流程，不攻击个人和群体。
- 使用“放大损失”时，只描述真实损失，不编造限时、稀缺、成本或恐惧。
- 原素材中的播放量是历史案例，不代表使用同一结构就能复现。

### 5. 默认交付格式

按此顺序交付：

1. **用户回报**：观众看完具体得到什么。
2. **推荐结构**：选择哪一种，以及为什么适合当前素材。
3. **可直接念的开头**：按 0–3、3–8、8–12、12–18 秒分段。
4. **两个备选钩子**：只改变开头变量，正文承诺保持一致。
5. **正文必须兑现的证据**：列出数据、案例、画面或演示。
6. **风险检查**：指出夸张、证据不足、争议或平台合规风险。

用户要求完整脚本时，在开头之后继续完成正文、分镜、字幕和自然收尾；不要只交付标题句。

## 交付前自检

- 第一秒是否已经进入观众的问题？
- 前 3 秒是否说明继续看的理由？
- 前 10–12 秒是否给出第一份有效回报？
- 结构是否与素材匹配，而不是为了刺激硬套公式？
- 正文是否能够兑现开头的每个承诺？
- 是否把案例播放量误写成结果保证？
- 是否存在虚假损失、虚假争议、攻击个人或情绪绑架？
- 实际念出来是否顺口，时长是否合理？
